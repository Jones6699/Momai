# 文脉协作：工作台 × InkFlow

本功能直接接入两个原项目：工作台仍负责正式资产与验收，InkFlow 仍负责移动对话写作。两端用 JSON 文件离线交接，不需要开放工作台服务到局域网。

## 使用流程

1. 在工作台创建并初始化小说、章节，准备世界观、角色卡、关系卡、语言风格、信息账本和本章锚点。点击标题旁的「文脉协作」，选择章节，导出章节资料 JSON。
2. 在 InkFlow 当前项目的聊天页点击「文脉」，导入资料 JSON。它会绑定到当前 InkFlow 项目，之后该项目的生成和重试都携带同一章节设定。建议一个 InkFlow 项目只对应一个工作台章节；换章时重新导入。
3. 在 InkFlow 写作、改写、切换版本。点击「文脉」选择一条 AI 回复，可在文本框内继续编辑，然后导出候选稿 JSON。Android 版本保存至系统 Documents 目录；网页版本通过浏览器下载。
4. 回到工作台的「文脉协作」，选择同一章节并导入候选稿。先预览，再点击采用。采用前的正式正文会备份到项目 `草稿/`；新正文进入原有「校验与验收」阶段。若桌面设定在导出后变化，导入或采用会被拒绝，需重新导出资料并核对稿件。
5. 原有校验通过后，在完成卡点击「通过」。文脉协作弹层可从正式正文提取「人物知情」「伏笔」候选事实，或手动添加。逐条检查、勾选、确认后写入信息账本；原文证据必须是本章正式正文中的逐字片段。未经章节验收或缺失证据的条目不能入账。AI 提取需要工作台已有可用模型配置；手工添加不需要。

## 数据边界

- JSON 文件含小说设定与正文，应按私密创作资料保存；InkFlow 调用用户配置的模型 API 时，绑定的章节设定会随请求发送。
- 移动稿首先进入 `草稿/`；只有作者点击采用才替换正式正文，替换前会留备份。
- 入账时保留旧信息账本备份于 `运行记录/账本备份/`，JSON 条目保留证据、来源章节与生效章节。MD 文件沿用原工作台的可读格式。
- 当前版本是文件交接，不包含云同步、自动事实确认或真实模型生成结果保证。

## 本地验证

工作台：`node web/handoff.test.mjs` 与 `python 工作流脚本/运行测试.py`。在中文 Windows 控制台运行后者时可先设置 `PYTHONIOENCODING=utf-8`。

InkFlow：`npm ci`、`npm run typecheck`、`npm run build`。Android APK 仍需本机 Android 构建环境；本次验证未调用真实模型 API，也未在实体手机上执行文件往返。
