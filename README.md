# 墨脉创作台

一个面向中文长篇创作者的本地 AI 小说工作台。

墨脉创作台把世界观、角色、关系、剧情、章节正文和校验报告沉淀为可编辑的本地文件，再通过可追溯的步骤流完成创作。它适合需要长期维护设定、反复修改章节、关注角色一致性和信息伏笔的作者。

> 项目定位：不是一次性生成器，而是一套“设定沉淀 → 上下文冻结 → 正文生成 → 校验验收 → 证据入账”的创作系统。

## 快速体验

| 资源 | 说明 |
| --- | --- |
| 启动脚本 | Windows 双击 `启动工作台.bat`；macOS / Linux 执行 `./启动工作台.sh` |
| 局域网模式 | Windows 双击 `启动局域网工作台.bat`；或使用 `NOVEL_LAN=1 node web/server.mjs` |
| 默认地址 | `http://127.0.0.1:4173` |
| 移动端协作 | 配合 [墨脉移动端](../InkFlow-master/README.md) 通过局域网配对直传章节资料和候选稿，JSON 文件可作备用 |
| 设计文档 | `docs/`、`portfolio/` |

启动后，先创建一个“原创”或“同人”项目，再按页面中的流程推进。

## 产品定位

### 适合谁

- 需要连续创作几十章或上百章的网文作者
- 需要维护角色关系、世界规则和伏笔状态的创作者
- 想在电脑端严谨管理项目，同时在手机端随时写作的人
- 希望保留本地文件、自己选择模型 API、避免被单一平台锁定的用户

### 核心原则

| 原则 | 具体做法 |
| --- | --- |
| 设定可追溯 | 世界观、角色卡、剧情和账本都以普通文件保存 |
| 过程可控 | 每个步骤支持下一步、撤回、重试和人工通过 |
| 上下文可核对 | 正文生成前形成提示词快照，减少设定遗漏 |
| 人工保留最终权 | AI 只能提出候选，正式正文和信息账本由作者确认 |
| 本地优先 | 小说内容保存在本地，模型请求使用用户自己的 API 配置 |

## 核心功能

### 1. 原创与同人两条创作路线

原创项目从小说资料、人物和剧情开始；同人项目可以上传原著文本，先提取文风、词汇和专有名词，再进入初始化和章节创作。

### 2. 初始化资产

初始化阶段可以建立：小说简介、世界观、语言风格、角色名单与角色卡、关系卡、剧情书与剧情卷、信息账本。这些文件既可以由模型生成，也可以在右侧文件面板中直接编辑。

### 3. 章节工作流

```text
强制设定锚点 → 本章配置 → 台词 → 最终提示词快照 → 正文 → 校验与验收
```

正文生成前会汇总本章所需的设定、角色、关系、剧情和风格资料。生成后，校验步骤会检查锚点落实、设定一致性、角色一致性、剧情衔接和文风表达。

### 4. 同人原著提取

同人项目支持 `.txt` 原著导入，并提供原文统计、高频词、原文风格、正向词库和专属词库提取步骤。提取结果会沉淀到项目文件中，后续章节可以继续使用。

### 5. 墨脉桥：桌面端与移动端协作

```text
桌面导出章节设定 → 手机墨脉导入并写作 → 导出候选稿
→ 桌面预览并采用 → 原有校验与验收 → 核对正文证据后更新信息账本
```

安全边界：候选稿不会自动覆盖正式正文；采用前会备份旧正文；设定版本变化后旧候选稿会被拒绝采用；未验收章节不能更新正式账本；每条“人物知情”或“伏笔”必须提供正文中的逐字证据；账本更新前会保存备份。

详细说明见 [墨脉桥移动端闭环](docs/文脉协作-移动端闭环.md)。

局域网模式下，电脑端生成短时配对码，手机和电脑连接同一 Wi-Fi 后即可直接交换章节资料和候选稿；也可以继续使用 JSON 文件方式。

可运行 `node web/lan-smoke.mjs` 检查局域网接口的完整交接链。脚本在系统临时目录创建模拟小说，完成后清理，不会修改真实小说项目。AI 写作和模型校验仍需自行配置模型 API。

## 界面结构

- 左栏：小说项目、卷、章节和项目切换
- 中栏：对话式流程、生成结果、校验卡片和操作按钮
- 右栏：正文、提示词、知识库、词汇库、剧情和提取文件

当前 UI 使用“暖纸张 + 靛青工作流 + 琥珀证据”的视觉系统，突出当前阶段、模型控制和证据入账状态。

## 技术架构

```text
墨脉创作台
├─ web/                  前端页面、本地 Node 服务和墨脉桥接口
├─ 工作流脚本/            Python 工作流引擎与步骤模块
├─ 小说项目/              本地小说数据
├─ docs/                  产品、技术和协作文档
└─ portfolio/             截图、展示页和作品素材
```

主要技术：Node.js 原生 HTTP 服务、Python 工作流、HTML/CSS/JavaScript 前端、OpenAI 兼容协议、JSON/Markdown/TXT 项目资产。

## 安装与运行

### 环境要求

- Node.js 18 或更高版本
- Python 3.11 或 3.12
- 一个 OpenAI 兼容的模型 API

### 一键启动

Windows：

```text
双击 启动工作台.bat
```

macOS / Linux / Git Bash：

```bash
./启动工作台.sh
```

### 手动启动

```bash
cd web
node server.mjs
```

然后打开 `http://127.0.0.1:4173`。

### 配置模型

在页面设置中填写提供方、API 地址、API Key、模型名称和思考强度。配置保存在 `工作流脚本/工作台设置.json`，该文件可能包含 API Key，请勿提交到公开仓库。

## 测试

```bash
# 全部套件：单元、流程、服务端、前端、验收
python 工作流脚本/运行测试.py

# 单独运行
python 工作流脚本/运行测试.py --suite 单元
python 工作流脚本/运行测试.py --suite 流程
python 工作流脚本/运行测试.py --suite 服务端
python 工作流脚本/运行测试.py --suite 前端
python 工作流脚本/运行测试.py --suite 验收

# 墨脉桥闭环测试
node web/handoff.test.mjs
```

真实模型验收会消耗 API 额度：

```bash
python 工作流脚本/运行测试.py --suite 验收 --live-model
```

## 注意事项

- 原著提取功能只应处理自己创作或拥有合法使用权的文本。
- 不要把 `工作流脚本/工作台设置.json` 提交到公开仓库。
- 建议定期备份 `小说项目/`，并使用 Git 保存重要版本。
- 模型生成结果仍需作者审核，校验通过不等于事实绝对正确。
- 本项目采用文件交接，不提供云端同步，也不会自动上传小说项目内容。
